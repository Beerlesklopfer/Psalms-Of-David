# Code review 2026-10-31

A review of the server (`server/`), the app (`app/`) and the sound engine (`audio/`) on branch `development` at `b3ab906`, made by
three reviewers (server access, server files and input, app and engine). Their findings were then argued over in two rounds by three
more: a **prosecutor** (fix now), a **defender** speaking for the maintainer (is it real, is the fix right for this design?) and a
**pragmatist** speaking for the family that runs it. Only what held up is fixed in this branch; the rest is listed below with the
verdict. Every finding was checked against the code; none is critical or high in the sense of "anyone on the internet takes the
server".

What was found good: tokens of sessions, devices, MCP and pairing are stored only as SHA-256 hashes, pairing codes are 128 bits and
single use, CSRF protection covers every form, cookies are `HttpOnly; SameSite=Strict` (and `Secure` with TLS), the `VISIBLE` rule is
applied to lists, details, covers, streams, playlists and search, downloads and streams resolve paths only inside the library,
outbound fetches allow public addresses only (also after redirects), the app pins the certificate on every connection to David
(REST, downloads, covers, WebSocket), and the FFI layer of the engine (handles with generation, `catch_unwind` on every export,
matching signatures) is solid.

Tests: 605 of 608 server tests passed before the changes; the 3 others need multicast and IPv6 in the network and a run as a user
other than root, which the review machine did not have (see README, "Entwicklung").

## Fixed in this branch

| Id | Finding | Fix | Test |
|---|---|---|---|
| F2 | **Podcast feed memory bomb.** `podcast.rs` parsed with `allow_dtd: true`; roxmltree limits nesting but not how often the document refers to an entity, so a 5 MiB feed with an internal DTD expands to terabytes. A child can follow a feed (it is fetched before approval), and the refresher parses it again on every round, so one bad feed takes the server down again and again. | A document that declares entities (`<!ENTITY`, allowed only in an internal DTD subset; no real feed has one) is refused; a plain public DOCTYPE (old RSS 0.91 feeds) stays allowed. The whole text is searched: a first version looked only at the first DOCTYPE and was passed by a decoy in a comment (found by the check of the fixes: 2 KB became 25 MB). `nodes_limit` set. One place covers every caller (app, admin web, MCP, refresher). | `podcast::tests` (billion laughs and the decoy refused, RSS 0.91 with its DOCTYPE still read) |
| S1 | **PIN lock bypassed by parallel attempts** (found in the debate). The lock was read from the reader before the PIN was checked and written afterwards; a burst of parallel attempts all passed the read, each got a guess. Measured on the old code: a right PIN sent as the 40th of a burst got through in 3 of 3 runs. Also, a locked account answered differently from an unknown name, which told which names exist. | Each attempt is counted in one writer statement before the PIN is checked, and refused unchecked while locked (`UPDATE … WHERE pin_locked_until IS NULL OR … <= now RETURNING`). The sign-in form answers a lock like a wrong name; the message says that signing in pauses after wrong PINs. A locked check takes as long as a real one. | `tests/auth.rs` (burst), `tests/web.rs` (same page for a locked and an unknown name) |
| S2 | **A PIN reset in the admin web kept the old sessions.** | The reset ends the user's browser sessions (an administrator resetting their own PIN keeps the one they use); paired devices stay, as when a user changes their own PIN (`Store::replace_pin`, shared with `change_pin`). The command `david reset-pin` still ends everything. | `tests/web.rs` |
| S3 | **Hiding told a child about books it may not see.** `POST /api/v1/me/hidden` accepted any existing book id and author name and listed the title back; 404 versus 200 also showed which ids exist. | Hiding a book or an author checks `VISIBLE` for the profile and answers 404 otherwise; the lists of hidden books and authors name only what the profile may see. Showing again works for whatever the profile hid itself, also after the book was rated higher. The MCP tool `hide_albums` (administrators) can still hide a book that is not released yet (`admin_set_book_hidden`). | `tests/library_hiding.rs` |
| F6 | **An upload replaced files of an album that was there.** The place comes from the tags; two uploads without tags both go to `Unknown/Unknown`, and `rename` replaced the files of the first. | An album whose file names are taken goes to `Title (2)`, `(3)`, …; a file is never replaced (hard link, or a copy into a new file). Two files of one album whose names become the same after cleaning get ` (2)` too. | `upload::tests` |
| A2 | **Two downloads of the same part could leave a broken file** marked as downloaded (playing and downloading a book for offline at the same time both wrote `<part>.part`). | A download of a file that is running already is waited for instead of started again; every download writes its own temporary file, and what a closed run left half loaded is deleted at the start. | `app/test/parallel_download_test.dart` |
| A3 | **A library reload that finished after "disconnect"** put the old account's library back into the player and the cache. | The reload and the outbox sync drop their result when the pairing changed meanwhile. | (by reading; no test harness for `_PsalmAppState`) |
| A4 | **The pairing file with the token** was briefly readable for other users on Linux (written, then `chmod 600`), not written atomically, and part of the Android backup. | Written to a new file that is made private while empty, then renamed over the old one. `server.json` is left out of the Android backup and device transfer (`res/xml/backup_rules.xml`, `data_extraction_rules.xml`). | (by reading) |

The app changes could not be run on the review machine (no Flutter SDK reachable); the CI of the pull request runs them.

The fixes were then checked by one more reviewer who had not seen the debate. It found the decoy bypass of F2, an author that could
get stuck in the hidden list (S3), half files piling up (A2) and two names of one album colliding (F6); all four are fixed above.
Left as notes: an upload into an album folder that exists with *other* file names is still merged into it (as before); where hard
links are not possible (exFAT, some network mounts) a file is copied instead of renamed; episodes downloaded for offline
(`podcast_downloads.dart`) still use their own downloader and can run twice next to playback (no longer into one file).

## Decided by the debate, not done here

- **S1, a lock that grows with repeated lockouts.** The prosecutor wanted up to 24 h, the defender up to 1 h, the pragmatist none,
  because a bored child at the sign-in page would lock a parent out for a day. With the race closed, the fixed 15 minutes and
  `pin_max_failures` allow 480 guesses a day from the LAN. **Owner's decision.** Proposals for later: lock per device or address
  rather than per account; show failed attempts on the overview of the administration.
- **S1, longer PINs for administrators.** Dropped: the owner decided "4 to 12 digits" (`spec-admin-ui.md`).
- **A1, mDNS re-addressing without a pinned certificate** sends the token in clear to whoever answers. Downgraded to low: a pairing
  without fingerprint exists only for a server on loopback (TLS is on for every other address, `tls.rs`), so only the Linux desktop app
  on the server machine itself is affected. Two-line guard in `main.dart` (no re-addressing when `fingerprint` is empty).

## Backlog (in the order of the debate)

1. **F1** Decompression bomb guard: for `.gz`, `.bz2` and `.xz` the size 7-Zip lists is the one the archive claims (or none), so the
   limit and the free-space check can be passed and the disk filled. Minimal: refuse single-stream archives without a trustworthy size;
   later: count the bytes while unpacking and stop, and a time limit for `7z x`. Only administrators upload.
2. **A5** The engine cuts an error message at a byte, not a character (`audio/src/ffi.rs:187`); Dart's strict UTF-8 then throws on
   every tick. Cut at a character boundary, decode with `allowMalformed`.
3. **F3** Links inside archives are dropped only after unpacking; an old p7zip can write through a link entry. Refuse entries with
   `Symbolic Link`, `Hard Link`, absolute paths or `..` in the listing.
4. **A4, rest** The token in the keystore/keychain (`flutter_secure_storage` or similar) and the iCloud backup exclusion on iOS
   (`spec-app-api.md` lists it as not done).
5. **A6** Skipping back at the very start of a book can send a negative start position to the engine (`state_machine.dart`); clamp to 0.
6. **A9** `lock().unwrap()` in `audio/src/core.rs` lets a poisoned lock end the engine thread silently.
7. **A8** Episodes played from the publisher have no size limit and may be redirected from https to http (`server_source.dart`).
8. **F7** Names are cut by characters, not bytes (120 in `upload.rs`, 150 in `relocate.rs`); long names in multi-byte letters exceed
   the 255-byte limit of file systems.
9. **S4** MCP tokens keep working after the administrator who made them is demoted or deleted.
10. **S5, S6** A member can give any podcast to any profile, and cancel another user's CD rip.
11. **S7** The device name of a pairing request is logged with control characters (log lines can be forged without signing in).
12. Smaller: `spawn_blocking` for Argon2; the role of a shared device is not lowered yet (not reachable today); `HttpClient`s
    not closed when the pairing changes (`main.dart`); the address check of outbound fetches is passed when a proxy is set in the
    environment (ureq takes it from there; set `.proxy(None)`) and misses NAT64/6to4 and two IPv4 test ranges.
